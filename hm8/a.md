## Поточный парсер CSV с заданным разделителем

Реализуйте поточный (streaming) парсер CSV-файлов с заданным разделителем и сравнить его с нативной обработкой JSON.

**Что нужно сделать:**

- Написать парсер, который читает CSV построчно (или по чанкам), не загружая весь файл в память.
- Протестировать на файле ≥10 МБ, сравнив с аналогичными данными в JSON (используя `JSON.parse`).
  - Измерить и сравнить:
    - Общее время обработки
    - Время до первой записи (latency до начала получения данных)
    - Пиковое потребление памяти
    - Размер данных в CSV и JSON БЕЗ и СО сжатием

- (со звёздочкой): Добавить поддержку экранирования разделителя (например, "a,b" или a\,b).

import * as fs from "node:fs";
import * as readline from "node:readline";

  });
}

### Отчет по результатам парсинга CSV и JSON: производительность, память и сжатие

#### Цель эксперимента

Сравнить производительность, потребление памяти и эффективность сжатия двух форматов данных:

- **CSV** (потоковая обработка)
- **JSON** (полная загрузка в память)

#### Характеристики исходных файлов

| Параметр               | CSV        | JSON       |
| ---------------------- | ---------- | ---------- |
| **Размер файла**       | 81.29 MB   | 194.78 MB  |
| **Количество записей** | одинаковое | одинаковое |

CSV оказался более чем в **2.4 раза компактнее** исходного JSON (81 MB против 195 MB). Это объясняется отсутствием
повторяющихся ключей в каждой строке — в CSV заголовки вынесены отдельно, а в JSON каждый объект хранит полные имена
полей (`"id"`, `"name"`, `"score"` и т.д.), а также скобки, кавычки и запятые.

---

#### Производительность парсинга

| Показатель                 | CSV (потоковый) | JSON                    |
| -------------------------- | --------------- | ----------------------- |
| **Время до первой записи** | 6.36 ms         | N/A (весь файл целиком) |
| **Общее время парсинга**   | 281 ms          | 542 ms                  |
| **Heap Used (пик)**        | ~10 MB          | ~391 MB                 |
| **RSS (пик)**              | ~57 MB          | ~506 MB                 |

**Выводы по парсингу:**

- JSON парсится в **1.9 раза медленнее** (542 ms против 281 ms)
- JSON потребляет **в 40 раз больше** оперативной памяти (391 MB против 10 MB)
- CSV показывает первую строку уже через **6.36 ms** — критично для интерактивных систем
- CSV можно обрабатывать файлы любого размера, JSON упирается в лимиты памяти

---

#### Потоковый парсинг JSON

Важное уточнение: **JSON тоже можно парсить потоково**, но это сопряжено с ограничениями:

##### 1. JSON Lines (JSONL) — каждая строка отдельный JSON объект

```jsonl
{"id":1,"name":"Alice"}
{"id":2,"name":"Bob"}
```

- ✅ Можно парсить построчно (как CSV)
- ✅ Простая реализация
- ❌ **Это уже не валидный JSON массив** (не начинается с `[` и не заканчивается `]`)
- ❌ Не совместим с API, ожидающими стандартный JSON

##### 2. Стандартный JSON массив — реализация кастомного потокового парсера

```json
[
  {
    "id": 1,
    "name": "Alice"
  },
  {
    "id": 2,
    "name": "Bob"
  }
]
```

- ✅ Технически возможно
- ❌ Сложная реализация
- ❌ Работает **медленнее нативного JSON.parse()** (из-за JS-реализации)
- ❌ Всё равно медленнее потокового CSV, так как нужно парсить скобки/кавычки/экранирование

**Итог:** Да, JSON можно обрабатывать потоково, но это либо нарушает стандартный формат (JSONL), либо работает
медленнее. CSV выигрывает в этой области за счёт своей простоты.

---

#### Гибкость форматов: что с вложенными данными?

**Ограничение CSV:** формат не поддерживает вложенные структуры. Все данные должны быть плоскими.

**Решение — компромисс:** внутрь ячейки CSV можно положить JSON:

```csv
id,name,metadata
1,Alice,"{""age"":30,""city"":""Moscow""}"
2,Bob,"{""age"":25,""city"":""SPb""}"
```

**Плюсы такого подхода:**

- ✅ Основные данные плоские (быстрый доступ)
- ✅ Вложенные данные сохраняются (через JSON внутри)
- ✅ Можно парсить потоково (CSV построчно)

**Минусы:**

- ❌ Усложнение кода (нужно дополнительно парсить внутренний JSON)
- ❌ Внутренний JSON всё равно загружается целиком для каждой строки

**Вывод:** CSV подходит только для простых, плоских данных. Для сложных иерархий JSON — естественный выбор. Компромисс —
CSV с JSON внутри, но это палка о двух концах.

---

#### Эффективность сжатия (уровень 5 — оптимальный баланс)

Сжатие на уровне 5 даёт **лучшее соотношение скорость/размер** для реальных сценариев:

| Формат   | Исходный  | ZIP            | Brotli             | Gzip           |
| -------- | --------- | -------------- | ------------------ | -------------- |
| **CSV**  | 81.29 MB  | 28.51 MB (65%) | **26.50 MB (67%)** | 28.51 MB (65%) |
| **JSON** | 194.78 MB | 33.91 MB (83%) | **31.52 MB (84%)** | 33.91 MB (83%) |

##### Ключевое наблюдение

**JSON значительно сильнее нуждается в сжатии, чем CSV:**

- CSV без сжатия уже компактен (81 MB)
- JSON без сжатия очень большой (195 MB) — почти в 2.5 раза больше CSV

После сжатия на уровне 5 разрыв между форматами **драматически сокращается**:

- Исходная разница: **113.5 MB** (CSV меньше в 2.4 раза)
- После Brotli: всего **5 MB** (CSV — 26.50 MB, JSON — 31.52 MB)

**Парадокс:** JSON, который изначально был в 2.4 раза больше, после сжатия становится всего на 19% больше CSV. Это
происходит потому, что алгоритмы сжатия (особенно Brotli) отлично находят повторяющиеся паттерны — ключи объектов,
кавычки, скобки — и эффективно их устраняют.

**Для передачи по сети:** JSON жизненно необходимо сжимать, иначе он будет в 2.4 раза тяжелее CSV. CSV можно передавать
и без сжатия.

---

#### Время сжатия (уровень 5)

| Формат   | ZIP    | Brotli | Gzip   |
| -------- | ------ | ------ | ------ |
| **CSV**  | 0.81 с | 1.64 с | 0.78 с |
| **JSON** | 1.23 с | 1.81 с | 1.21 с |

**Вывод:** На уровне сжатия 5 время становится **приемлемым для динамических систем**:

- CSV сжимается Brotli за **1.64 секунды**
- JSON сжимается Brotli за **1.81 секунды**

Это уже можно использовать для кэширования, но для высоконагруженных API лучше отдавать несжатые данные.

---

#### Максимальный уровень сжатия (уровень 9)

Сравнение с результатами на уровне 9:

| Формат                      | CSV (уровень 5) | CSV (уровень 9) | JSON (уровень 5) | JSON (уровень 9) |
| --------------------------- | --------------- | --------------- | ---------------- | ---------------- |
| **Размер после Brotli**     | 26.50 MB        | **19.84 MB**    | 31.52 MB         | **21.42 MB**     |
| **Время сжатия Brotli**     | 1.64 с          | **80.78 с**     | 1.81 с           | **179.64 с**     |
| **Дополнительная экономия** | —               | +6.7 MB         | —                | +10.1 MB         |

##### Вывод о максимальном уровне сжатия

Максимальный уровень сжатия (9) даёт дополнительную экономию 6-10 MB, но ценой **неприемлемого времени** — от 80 секунд
для CSV до 3 минут для JSON.

**Область применения уровня 9 — только статические данные:**

- ✅ Архивы и бэкапы (сжимается один раз, распаковывается много раз)
- ✅ NPM-пакеты, Docker-образы (distributive артефакты)
- ✅ Статические ассеты на CDN (сжимаются при сборке)
- ❌ **Абсолютно не подходит для сжатия "на лету" в серверных приложениях**

Для динамических ответов сервера максимальный уровень сжатия неприменим — время ожидания в 80-180 секунд для одного
запроса неприемлемо.

---

#### Сравнение алгоритмов сжатия (уровень 5)

| Алгоритм   | CSV (размер/время) | JSON (размер/время) | Вердикт                            |
| ---------- | ------------------ | ------------------- | ---------------------------------- |
| **ZIP**    | 28.51 MB / 0.81 с  | 33.91 MB / 1.23 с   | Хорошая скорость, среднее сжатие   |
| **Gzip**   | 28.51 MB / 0.78 с  | 33.91 MB / 1.21 с   | Самый быстрый, совместим везде     |
| **Brotli** | 26.50 MB / 1.64 с  | 31.52 MB / 1.81 с   | Лучшее сжатие, приемлемая скорость |

**Рекомендации по выбору алгоритма:**

- **Gzip** — для максимума совместимости и скорости (поддерживается везде)
- **Brotli** — для лучшего сжатия, если клиенты современные (браузеры)
- **ZIP** — для архивов и файлового хранения

---

#### Итоговые выводы

##### 1. JSON жизненно необходимо сжимать, CSV — опционально

| Формат   | Без сжатия | Со сжатием (Brotli 5) | Эффект                 |
| -------- | ---------- | --------------------- | ---------------------- |
| **CSV**  | 81 MB      | 26.5 MB               | Хорошо, но не критично |
| **JSON** | 195 MB     | 31.5 MB               | **Критически важно**   |

CSV и так компактен. JSON без сжатия в 2.4 раза тяжелее — для сети это катастрофа.

##### 2. Максимальный уровень сжатия — только для статики

- Уровень 9 даёт +6-10 MB экономии ценой **80-180 секунд** ожидания
- Для динамических ответов (API, веб-серверы) используется уровень 5-6
- Уровень 9 подходит только для архивов, бэкапов, статических ассетов (сжимается один раз)

##### 3. Для потоковой обработки CSV вне конкуренции

- JSON можно парсить потоково, но:
  - Либо через JSONL (не стандартный JSON)
  - Либо через кастомный парсер (медленнее нативного)
- CSV даёт лучшую скорость и минимальную память **из коробки**

##### 4. Главный компромисс: сложность данных vs производительность

| Требования              | CSV                | JSON         | CSV + JSON внутри                 |
| ----------------------- | ------------------ | ------------ | --------------------------------- |
| **Плоские данные**      | ✅ Идеально        | ❌ Избыточно | ⚠️ Перебор                        |
| **Вложенные данные**    | ❌ Не поддерживает | ✅ Идеально  | ✅ Компромисс                     |
| **Потоковая обработка** | ✅ Отлично         | ⚠️ Сложно    | ✅ Хорошо                         |
| **Скорость парсинга**   | ✅ Быстро          | ⚠️ Медленнее | ⚠️ Медленнее (нужен доп. парсинг) |
| **Память**              | ✅ Минимум         | ❌ Много     | ✅ Минимум (внешний слой)         |

**Золотое правило:**

- **Простые данные** (логи, метрики, таблицы) → CSV
- **Сложные деревья** (конфиги, API ответы) → JSON
- **Когда нужно и то, и другое** → плоская часть в CSV, сложная как JSON внутри ячеек

##### 5. Рекомендации по выбору формата для разных сценариев

| Сценарий               | Формат            | Сжатие       | Уровень | Причина                                        |
| ---------------------- | ----------------- | ------------ | ------- | ---------------------------------------------- |
| **High-load API**      | CSV               | Нет          | —       | Минимальная задержка, потоковая обработка      |
| **REST API**           | JSON              | Brotli/Gzip  | 5       | Удобство работы, хорошее сжатие                |
| **Хранение логов**     | CSV               | Gzip         | 5       | Скорость сжатия, компактность                  |
| **Статические ассеты** | JSON              | Brotli       | 9       | Сжатие при сборке, выгода для клиента          |
| **Долгосрочный архив** | JSON              | Brotli       | 9       | Максимальная экономия места, время не критично |
| **Big Data (>1GB)**    | CSV потоковый     | Нет или Gzip | —       | Не упирается в память                          |
| **Сложные отчёты**     | CSV + JSON внутри | Gzip         | 5       | Компромисс между скоростью и структурой        |

```js
import * as fs from "node:fs";
import * as readline from "node:readline";

function formatMemory(bytes) {
  return `${(bytes / 1024 / 1024).toFixed(2)} MB`;
}

function logMemoryUsage(label) {
  const mem = process.memoryUsage();
  console.log(`\n${label}:`);
  console.log(
    `   Heap Used:  ${formatMemory(mem.heapUsed).padEnd(16)} (JS объекты)`,
  );
  console.log(
    `   Heap Total: ${formatMemory(mem.heapTotal).padEnd(16)} (выделено V8 под кучу)`,
  );
  console.log(
    `   External:   ${formatMemory(mem.external).padEnd(16)} (C++ объекты, буферы)`,
  );
  console.log(
    `   RSS:        ${formatMemory(mem.rss).padEnd(16)} (вся память процесса)`,
  );
}

function timeEnd(id) {
  console.log();
  console.log("=".repeat(100));
  console.timeEnd(id);
  console.log("=".repeat(100));
}

console.time("Общее время парсинга CSV");

let firstRead = false;

console.time("Чтение первой строчки");

logMemoryUsage("📊  До парсинга CSV", true);

await new Promise((resolve, reject) => {
  parseCSV("./users-csv.csv", /(?<!\\),/, (err, data) => {
    if (err != null) {
      reject(err);
      return;
    }

    if (!firstRead) {
      timeEnd("Чтение первой строчки");
      firstRead = true;
    }

    if (data.done) {
      resolve();
    }
  });
});

timeEnd("Общее время парсинга CSV");
logMemoryUsage("📊  После парсинга CSV (строки уже не хранятся)");

global.gc?.();

console.time("Время полного парсинга JSON");
JSON.parse(fs.readFileSync("./users-json.json", "utf8"));
timeEnd("Время полного парсинга JSON");

logMemoryUsage("📊  После парсинга JSON");

function parseCSV(file, separator, cb) {
  const rl = readline.createInterface({
    input: fs.createReadStream(file),
    crlfDelay: Infinity,
  });

  rl.on("line", (line) => {
    cb(null, { done: false, value: line.split(separator) });
  });

  rl.once("error", (err) => {
    cb(err);
  });

  rl.once("close", () => {
    cb(null, { done: true, value: undefined });
  });
}
```
