## Поточный парсинг CSV против MessagePack

Сравните ваш парсер CSV с MessagePack на больших файлах (файлы должны содержать одинаковый набор данных).
Оба парсера должны работать в потоке, не загружая данные целиком в память. Проанализируйте результат также, как и для JSON.

Для работы с MessagePack используйте <https://www.npmjs.com/package/msgpackr> (с помощью `PackrStream` и `UnpackrStream`).

### Отчет по результатам парсинга CSV и MessagePack: производительность, память и сжатие

#### Цель эксперимента

Сравнить производительность, потребление памяти и эффективность сжатия двух потоковых форматов данных:

- **CSV** (потоковая обработка, текстовый формат)
- **MessagePack** (потоковая обработка, бинарный формат)

---

#### Характеристики исходных файлов

| Параметр               | CSV        | MessagePack |
| ---------------------- | ---------- | ----------- |
| **Размер файла**       | 81.29 MB   | 60.88 MB    |
| **Количество записей** | одинаковое | одинаковое  |

**Ключевое наблюдение:** MessagePack оказался значительно компактнее CSV — **60.88 MB против 81.29 MB**, экономия около
25%. Это объясняется бинарной природой формата: числа хранятся в компактном бинарном представлении,
отсутствуют разделители в виде запятых и переводов строк в том объёме, как в CSV.

---

#### Производительность парсинга

| Показатель                 | CSV (потоковый) | MessagePack (потоковый) |
| -------------------------- | --------------- | ----------------------- |
| **Время до первой записи** | 5.27 ms         | **2.12 ms**             |
| **Общее время парсинга**   | 284 ms          | 298 ms                  |
| **Heap Used (пик)**        | ~9 MB           | ~13 MB                  |
| **RSS (пик)**              | ~60 MB          | ~77 MB                  |

**Выводы по парсингу:**

- **MessagePack показывает лучшее время до первой записи** — 2.12 ms против 5.27 ms у CSV (в 2.5 раза быстрее)
- Общее время парсинга практически одинаковое (разница ~14 мс в пользу CSV, что в пределах погрешности)
- MessagePack потребляет немного больше памяти: +4 MB Heap, +17 MB RSS, что является допустимой ценой за бинарный формат
  и поддержку сложных структур
- Оба формата демонстрируют минимальное потребление памяти по сравнению с JSON (десятки мегабайт против сотен)

---

#### Поддержка сложных форматов: ключевое различие

Это **самое важное различие** между форматами:

| Характеристика                   | CSV                                                           | MessagePack                                                      |
| -------------------------------- | ------------------------------------------------------------- | ---------------------------------------------------------------- |
| **Поддержка вложенных структур** | ❌ Нет (только плоские таблицы)                               | ✅ Да (объекты, массивы, вложенность)                            |
| **Типы данных**                  | ❌ Всё строки (int/float/boolean приходится парсить отдельно) | ✅ Нативные типы (числа, булевы, строки, null, массивы, объекты) |
| **Бинарные данные**              | ❌ Требуют кодирования (Base64 и т.д.)                        | ✅ Нативная поддержка                                            |
| **Гибкость схемы**               | ❌ Фиксированное количество колонок                           | ✅ Динамическая структура                                        |

**Что это значит на практике:**

CSV — идеальный выбор для **табличных данных**:

```csv
id,name,age,city
1,Alice,30,Moscow
2,Bob,25,SPb
```

MessagePack — подходит для любых **сложных иерархических данных**.

**CSV не может представить такие данные без костылей** (например, сериализации вложенных объектов в JSON).

---

#### Потоковая реализация: стандарт vs библиотеки

**Важное техническое замечание:**

- **CSV** — построчная потоковая обработка является **частью спецификации формата**. Каждая строка — это самостоятельная
  запись, разделённая переносами строк. Это позволяет использовать стандартные инструменты (`readline`) без
  дополнительных ухищрений.

- **MessagePack** — **потоковая обработка не является частью стандарта**. Оригинальная спецификация MessagePack
  предполагает, что весь массив сериализуется целиком. Возможность потокового чтения/записи — это **расширение,
  реализованное на уровне конкретных библиотек** (в данном случае `msgpackr` с её `PackrStream`/`UnpackrStream`).

**Последствия:**

- Потоковый MessagePack — это **vendor-specific решение**. При смене библиотеки можно потерять эту возможность.
- Совместимость между разными реализациями потокового MessagePack не гарантирована.
- CSV с потоковой обработкой — это **универсальный стандарт**, который работает в любом языке и любой библиотеке.

---

#### Эффективность сжатия (уровень 5 — оптимальный баланс)

Сжатие на уровне 5 даёт **лучшее соотношение скорость/размер** для реальных сценариев:

| Формат          | Исходный | ZIP            | Brotli             | Gzip           |
| --------------- | -------- | -------------- | ------------------ | -------------- |
| **CSV**         | 81.29 MB | 28.51 MB (65%) | **26.50 MB (67%)** | 28.51 MB (65%) |
| **MessagePack** | 60.88 MB | 27.21 MB (55%) | **25.14 MB (59%)** | 27.21 MB (55%) |

**Наблюдения:**

- CSV сжимается лучше в процентном соотношении (67% против 59%), так как имеет больше текстовой избыточности
- **Абсолютный размер после сжатия почти одинаков** — CSV: 26.50 MB, MessagePack: 25.14 MB (разница всего 1.36 MB)
- MessagePack изначально компактнее, поэтому сжатие даёт меньший процент экономии, но финальный размер всё равно чуть
  меньше

**Вывод:** После сжатия оба формата становятся практически одинаковыми по размеру. Преимущество MessagePack в
компактности нивелируется хорошими алгоритмами сжатия.

---

#### Время сжатия (уровень 5)

| Формат          | ZIP    | Brotli | Gzip   |
| --------------- | ------ | ------ | ------ |
| **CSV**         | 0.81 с | 1.64 с | 0.78 с |
| **MessagePack** | 1.04 с | 0.93 с | 1.03 с |

**Интересное наблюдение:** MessagePack сжимается Brotli **быстрее**, чем CSV (0.93 с против 1.64 с), вероятно, из-за
меньшего размера и бинарной структуры, которая требует меньше анализа.

---

#### Максимальный уровень сжатия (уровень 9)

| Формат          | Размер (Brotli 9) | Время сжатия | Экономия к уровню 5 | Цена за MB  |
| --------------- | ----------------- | ------------ | ------------------- | ----------- |
| **CSV**         | 19.84 MB          | 80.78 с      | 6.66 MB             | 12.1 сек/MB |
| **MessagePack** | 20.57 MB          | 77.32 с      | 4.57 MB             | 16.9 сек/MB |

**Вывод:** Максимальный уровень сжатия, как и в случае с JSON, подходит **только для статических данных**.
Дополнительная экономия 4-6 MB достигается ценой ~80 секунд ожидания — неприемлемо для динамических систем.

---

#### Сравнение алгоритмов сжатия (уровень 5)

| Алгоритм   | CSV (размер/время) | MessagePack (размер/время) | Вердикт                             |
| ---------- | ------------------ | -------------------------- | ----------------------------------- |
| **ZIP**    | 28.51 MB / 0.81 с  | 27.21 MB / 1.04 с          | Стабильный результат                |
| **Gzip**   | 28.51 MB / 0.78 с  | 27.21 MB / 1.03 с          | Самый быстрый, везде поддерживается |
| **Brotli** | 26.50 MB / 1.64 с  | **25.14 MB / 0.93 с**      | **Лучшее сжатие для MessagePack**   |

**Для MessagePack Brotli оказывается не только самым эффективным по размеру, но и самым быстрым!** Это важное отличие от
CSV, где Brotli медленнее.

**

##### 2. Главное преимущество MessagePack — поддержка сложных структур

CSV — это **только плоские таблицы**. MessagePack поддерживает:

- Вложенные объекты и массивы
- Разные типы данных нативно (числа, булевы, null)
- Бинарные данные
- Произвольную глубину вложенности

**Если данные имеют иерархическую структуру — выбор очевиден в пользу MessagePack.**

##### 3. Важное ограничение: потоковая обработка MessagePack — не стандарт

- CSV построчно обрабатывается **везде** — это часть спецификации формата
- Потоковый MessagePack — это **расширение конкретной библиотеки** (`msgpackr`)
- При смене библиотеки или языка потоковая обработка может стать недоступной

##### 4. Сжатие: финальный размер почти одинаков

| Формат      | Исходный | После Brotli 5 | Экономия |
| ----------- | -------- | -------------- | -------- |
| CSV         | 81 MB    | 26.5 MB        | 67%      |
| MessagePack | 61 MB    | 25.1 MB        | 59%      |

После сжатия разница минимальна (1.4 MB). **Выбор должен определяться не размером, а структурой данных.**

##### 5. Максимальный уровень сжатия — только для статики

Уровень 9:

- Экономит ещё 4-6 MB
- Требует 77-80 секунд сжатия
- **Неприменим для динамических систем**
- Подходит только для архивов, бэкапов, статических ассетов

##### 6. Рекомендации по выбору формата

| Сценарий                                                     | Выбор       | Причина                                       |
| ------------------------------------------------------------ | ----------- | --------------------------------------------- |
| **Плоские табличные данные** (логи, метрики, экспорты из БД) | CSV         | Простота, универсальность, минимальная память |
| **Иерархические данные** (конфиги, API-ответы, документы)    | MessagePack | Поддержка вложенности, бинарные данные, типы  |
| **Высокая нагрузка с большими объёмами**                     | CSV         | Минимальное потребление памяти                |
| **Важна скорость доступа к первым данным**                   | MessagePack | 2.12 ms против 5.27 ms                        |
| **Требуется совместимость с разными системами**              | CSV         | Абсолютный стандарт                           |
| **Экосистема JS/Node.js**                                    | MessagePack | Отличная поддержка, нативное ускорение        |

---

#### Главный вывод эксперимента

**CSV и MessagePack — инструменты для разных задач:**

- **CSV** — король **простых табличных данных** и **универсальной совместимости**. Потоковая обработка заложена в
  стандарт, потребление памяти минимально.

- **MessagePack** — выбор для **сложных иерархических данных**. Компактнее CSV, быстрее отдаёт первые записи,
  поддерживает типы и вложенность. Но потоковая обработка — это нестандартное расширение, завязанное на конкретные
  библиотеки.

**Если ваши данные — плоская таблица → берите CSV. Если структура сложная и иерархическая → MessagePack ваш выбор.**

Максимальный уровень сжатия (9) оставьте для статических артефактов. В динамических системах используйте уровень 5 — он
даёт 90% эффективности при 1% затрат времени.

function parseCSV(file, separator, cb) {
    const rl = readline.createInterface({
        input: fs.createReadStream(file),
        crlfDelay: Infinity
    });

    rl.on('line', (line) => {
        cb(null, {done: false, value: line.split(separator)});
    });

    rl.once('error', (err) => {
        cb(err);
    });

    rl.once('close', () => {
        cb(null, {done: true, value: undefined});
    });
}
